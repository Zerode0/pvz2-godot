## 普通运行

执行 Tools/setup.ps1，然后执行 Tools/project.ps1 Run。已入库资产直接运行，无需重新转换 PAM 或重新导出地图。

环境固定信息集中在 Tools/team-environment.json。Godot 4.7.2 官方 Windows ZIP 的 SHA-256 为 731980f9608d61333e5baf54a2ef17210acc7a538446c0cb9969f002aca1e953。

## 素材处理

执行 Tools/setup.ps1 -AssetTools 后，用 Tools/.venv/Scripts/python.exe 运行 Python 脚本。Pillow、Playwright 版本见 Tools/requirements-assets.txt；TypeScript 5.6.3 由 reference/dragonbones-tooling/compiler/package-lock.json 固定。

| 任务 | 入口与输入 |
| --- | --- |
| 转换新 PAM | 读 pvz2-pam-convert skill；使用 scripts/convert_pam.mjs 和其 --worker-dir、--input、--output-dir 参数 |
| 配对图片或图集 | 读 pvz2-texture-map skill；使用已有索引或配套 PNG，输出本次角色子集 |
| 重新准备加载花 | node Tools/bake_loading_flower.mjs；输入 reference/pam-resources/original-loading-flower/ 和官方 DragonBones core |
| 重新采样已有地图动画 | node Tools/sample_world_map.mjs；输入 reference/world-map/ 与 dragonBones-core.js |
| 完整重新导出地图或植物图鉴 | 先准备下面的固定参考工程，再按资产 SOURCE.md 中的命令执行 |

地图/图鉴的完整重导出使用 Gardendless 固定提交 462f1161d5a29423409002936f2e05f1c24ac630。需要时执行 Tools/fetch-reference.ps1 获取到忽略提交的 reference/research/pvzge_web-readonly/。这一步下载外部完整参考构建，体积和时间明显大于普通配置。导出脚本通过 Playwright 调用其原生 Cocos API，使用已安装的 Microsoft Edge。

源码目录已经存在时 fetch-reference.ps1 会保留它；下载中断留下的目录需要先由 AI 检查现有 Git 状态，继续获取固定提交。脚本不会清空本地参考目录。

早期 Tools/prepare_scene_assets.py、prepare_level_assets.py、prepare_pam_example.py、prepare_world_map_assets.py 依赖本机完整 SourceAssets。当前已提交这些脚本的产出；只有重新提取或配图时才需要原库。新成员新增角色可以先复用 reference/pam-resources/ 的配套资源，缺少的素材按资源查找 skill 补齐。
