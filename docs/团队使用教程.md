# 团队使用教程

适用于 Windows，成员主要通过 AI 修改项目。所有命令从仓库根目录执行，可直接让 AI 代为操作。

## 1. 第一次加入

安装 Git for Windows，登录自己的 AI 编程工具。在准备存放项目的文件夹打开 PowerShell，执行：

~~~powershell
git clone https://github.com/Zerode0/pvz2-godot.git
cd pvz2-godot
powershell -NoProfile -ExecutionPolicy Bypass -File Tools/setup.ps1
~~~

也可以将仓库地址交给 AI，让它克隆并执行配置。配置脚本从 Godot 官方 GitHub 下载 4.7.2 Windows 版本，校验 SHA-256，放入 Tools/Godot/4.7.2/ 并导入工程。需要联网；已准备好的引擎会直接复用。日常游戏开发与试玩不需要安装 Python、Node 或原始完整素材库。

配置完成后双击 **启动游戏.cmd**。正常流程是 Play → 进入世界 → 前院第一关 → 开始关卡 → 开始防守。其他世界目前可以浏览。

## 2. 让 AI 读懂项目

在 AI 工具中打开仓库根目录，避免只打开 GodotPamDemo 子目录。

| 工具 | 仓库提供的入口 |
| --- | --- |
| Codex | AGENTS.md 与 .agents/skills/ |
| Claude Code | CLAUDE.md 引入 AGENTS.md |
| Cursor | .cursor/rules/project.mdc 指向项目规则和技能 |
| 其他工具 | 在首次消息要求读取 AGENTS.md 和对应 SKILL.md |

可以复制这段消息开始：

> 这是团队的 PvZ2 Godot 项目。先读取根目录 AGENTS.md 和 .agents/skills/pvz2-team-workflow/SKILL.md，再按本次任务读取功能技能。检查环境并启动游戏。后续修改使用独立任务分支，完成后提供试玩步骤和检查结果。

技能是随仓库提交的普通文件。团队流程、角色接入、PAM 转换、贴图配对、动画绑定、UI、植物图鉴各有对应技能，AI 按任务读取。没有 PAgent 的成员可以使用自己的 AI；本机已有 PAgent Luna 的成员沿用自己的配置，凭据由成员自行管理。

## 3. 开始一次修改

先在群里说明准备修改的内容，将相关讨论结论提供给 AI。让 AI 同步主分支并创建任务分支，例如：

~~~powershell
git switch main
git pull --ff-only
git switch -c codex/peashooter-balance
~~~

若工作区已有未提交修改，先让 AI 查看并处理当前任务，避免混入下一项任务。分支名描述任务即可。成员可以修改植物、僵尸、关卡、战斗系统、界面和素材，按每次任务协调范围。

例如：

> 群里决定把豌豆射手的发射间隔调整为 1.8 秒，费用保持 100。请按项目技能修改，启动测试关卡让我试玩，并检查第一关仍能正常进行。

修改既有玩法查 data/actors.json 与 scripts/runtime/；新机制需要实际实现行为。角色接入和动画方法由相应技能说明。所有必要素材、数据、脚本随同一次 PR 提交。

## 4. 运行与测试

双击 **测试关卡.cmd** 打开统一测试关卡。它使用正式关卡同一套种植、战斗、动画事件和实体系统，能够选植物、指定行刷怪、设置阳光、取消冷却、暂停和清场。详见 [开发测试关卡](开发测试关卡.md)。

需要编辑场景时运行：

~~~powershell
powershell -ExecutionPolicy Bypass -File Tools/project.ps1 Editor
~~~

Godot 编辑器 F5 运行整个游戏，F6 运行当前场景。修改完成后，让 AI 选择相关检查：

~~~powershell
powershell -ExecutionPolicy Bypass -File Tools/project.ps1 Check
powershell -ExecutionPolicy Bypass -File Tools/project.ps1 Verify -Suite level -Headless
powershell -ExecutionPolicy Bypass -File Tools/project.ps1 Verify -Suite sandbox -Headless
~~~

其他回归套件为 transition、world-map、plant-preview；all 执行全部。需要真实画面或输入时去掉 -Headless。截图和结果写入 Artifacts/，默认不提交。自动检查通过后，由成员实际试玩本次效果。当前 CI 会检查工程导入、第一关和开发测试关卡，不代替玩法和平衡验收。

## 5. 提交修改和 PR

仓库所有者先在 GitHub Settings → Collaborators 邀请团队成员，成员接受邀请后即可推送任务分支。首次 Git 提交前设置自己的姓名和邮箱：

~~~powershell
git config user.name "你的名字"
git config user.email "你的 GitHub 提交邮箱"
~~~

向 AI 提出：

> 把本次已经完成并测试的修改整理成提交，推送当前任务分支并创建 PR。说明修改内容、试玩方法和实际检查结果，使用仓库 PR 模板。

AI 可以使用 GitHub CLI（若已安装并登录），也可以让成员在推送后点击 GitHub 的 Compare & pull request。PR 目标为 main，选择自己的任务分支。没有安装 CLI 时不影响 Git 推送和网页创建 PR。

## 6. 定期整合

按群里约好的时间整合。合并前在任务分支同步主分支：

~~~powershell
git fetch origin
git merge origin/main
~~~

由 AI 处理代码冲突；涉及机制取舍的冲突先在群里达成一致，再提供给 AI。确认相关检查和试玩通过后，在 GitHub 使用 **Squash and merge**，让一个 PR 对应一份可撤回的修改。没有固定审批人，团队成员根据约定自行整合。

整合后其他成员更新 main。任务合并后可以删除远程任务分支。若合并后发现问题，让 AI 对该 PR 的 squash 提交执行 git revert，再通过修复 PR 合回主分支。

## 7. 新增素材

已提交素材可以直接使用。只有转换 PAM、裁切图集或重新导出地图等素材任务需要额外工具：

~~~powershell
powershell -ExecutionPolicy Bypass -File Tools/setup.ps1 -AssetTools
~~~

脚本在缺少时通过 winget 安装 Python/Node，在 Tools/.venv/ 准备 Python 依赖，并安装锁定的 TypeScript。浏览器导出使用 Windows 自带或已安装的 Microsoft Edge。

启动游戏使用已提交素材即可。新增素材按 [资源与工具](资源与工具.md) 和对应技能操作；将最终需要的文件及来源记录一并提交。

## 常见情况

| 情况 | 处理 |
| --- | --- |
| 双击游戏提示找不到 Godot | 先运行 配置环境.cmd，或执行 Tools/setup.ps1 |
| 首次导入较慢 | 等待素材导入完成，再启动游戏 |
| 下载校验失败 | 脚本会移除失败下载；检查网络后重新运行配置 |
| 下载中断后缓存不完整 | 再运行一次配置会校验并清理；随后重新下载 |
| 出现脚本错误或缺资源 | 让 AI 读取具体输出，执行 Check 并核对本次文件和路径 |
| AI 未自动读取 skill | 直接给它 AGENTS.md 和所需 SKILL.md 的路径，要求先读取 |
| 缺少 SourceAssets 原图 | 当前游戏可以直接运行；全库提取任务需要另取原始素材，或从已有配套资源准备本次子集 |
| 群内机制与 AI 理解不同 | 将相关群聊结论补充到当前 AI 对话 |
