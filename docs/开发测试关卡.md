# 开发测试关卡

双击仓库根 **测试关卡.cmd**，或执行：

~~~powershell
powershell -ExecutionPolicy Bypass -File Tools/project.ps1 TestLevel
~~~

初始为空草坪、5000 阳光，不自动刷怪。空场保持运行，方便反复测试；测试结果不会写入世界地图通关记录。

## 操作

| 控件 | 用途 |
| --- | --- |
| 植物选择器 | 读取同一 actor catalog 内所有植物；选择后点击草坪种植 |
| 僵尸选择器、行选择器 | 选择角色与第 1～5 行，点击“生成僵尸” |
| 阳光数值、设置阳光 | 设置当前阳光 |
| 无限阳光 | 保持充足阳光，默认关闭 |
| 取消种植冷却 | 可以连续种植，默认关闭 |
| 清空草坪 / 重新开始 | 清除实体、弹体、拾取物并重置单局，保留辅助开关 |
| 原关卡暂停、倍率和铲子 | 按正式逻辑运行；暂停时不能种植或刷怪 |
| 返回世界地图 | 离开测试，回到现有游戏地图 |

测试费用、冷却时关闭辅助选项；测试攻击和动画时可以开启。角色到达失败线仍会触发失败，点击重新开始继续。

## AI 接入接口

scenes/development_sandbox.tscn 继承 level_01.tscn；DevelopmentSandbox 继承 FrontyardLevel，共用 LevelSession、PlantingSystem、CombatSystem、PickupSystem 和 PAM 播放器。

data/levels/development_sandbox.json 的 actor_catalog 指向实际角色目录。新增角色后，选择器自动读取目录；新增机制应在对应实体或系统实现。spawn_test_zombie(kind, row) 的行索引从 0 开始。场景关闭 automatic_victory，正式关卡保持默认开启。

`spawn_test_zombie()` 复用 `LevelSession.spawn_zombie(kind, row)`；后者返回实际僵尸或 null。显式种植使用 `plant(kind, cell)`，查询使用 `check_placement(kind, cell)`，读取状态使用 `get_run_state()`。完整启动参数、操作、返回值和验证入口见 [单局公共接口](../GodotPamDemo/docs/runtime-interfaces.md)。

现有第一关顶部牌组仍按三卡布局；测试关卡的选择器支持目录内更多植物。扩大正式关卡牌组时按 UI skill 调整布局。

验证入口：Tools/project.ps1 Verify -Suite sandbox，支持 -Headless；成功标记为 DEVELOPMENT_SANDBOX_OK。有画面时保存 Artifacts/development-sandbox/sandbox.png。
