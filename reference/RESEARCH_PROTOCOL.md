# 源码调研子 agent 协议

## 角色与范围

- 主 agent 负责选型、核查关键结论和向用户汇总；子 agent 核查指定仓库实际代码。
- 默认只读调研；可把源码快照与报告存入 `reference/`，不得修改游戏工程。
- 不执行构建、打包、发布、部署或覆盖最终制品，不调用其他 agent。
- 用户提供的信息属于待核实线索，不自动作为已验证结论。

## 固定读取顺序

1. 本协议。
2. `reference/SOURCE_RESEARCH.md`。
3. `reference/ADDITIONAL_SOURCES.md`。
4. 本轮指定仓库的 README、LICENSE、依赖清单及实际入口代码。
5. 与本轮问题有关的资源、动画、玩法代码；不要泛读无关内容。

## 输出

- 简述技术栈、许可证、实际完成范围。
- 列出可直接复用、需要移植及仅可参考的部分，给出源码路径与链接。
- 区分实际读到的代码、作者声明及尚未运行验证的能力。
- 给出适用于 Godot 4 的推荐路线、关键限制和下一步最小验证。
- 长任务提供阶段结果；网络失败时说明缺口，不反复重试。
